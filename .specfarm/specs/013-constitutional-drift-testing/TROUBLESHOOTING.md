## Executive Summary

The experiment framework executed successfully at the mechanical level (15/15 runs completed, all `run-report.json` files produced). However, **5 stub/dead features** were identified that fundamentally undermine the validity of the experiment results. The most critical: **`EvidenceAccuracy` and `SemanticSimilarity` are generated by `awk rand()` — they are random numbers, not real measurements.** Every SC-001/002/003 failure traces back to this.

## STUB-001 — `EvidenceAccuracy` and `SemanticSimilarity` are random (not computed)

**Severity**: 🔴 CRITICAL  
**File**: `experiment_harness.sh` lines 137–144  
**Status**: ACTIVE in production experiment runs

### What the spec says
- `EvidenceAccuracy`: Fraction of gathered rules with verifiable evidence in the codebase [0.0–1.0]
- `SemanticSimilarity`: Coherence of rule signatures against baseline [0.0–1.0]
- Both feed the composite `DriftScore` formula

### What actually happens
```bash
# Lines 137-144 of experiment_harness.sh (the version in the spec dir)
SEED=$(( _NS + $$ + RUN_NUM * 97 ))
EVIDENCE_ACCURACY=$(awk -v seed="$SEED" "BEGIN {srand(seed); printf \"%.6f\", rand() * 0.2 + 0.80}")
SEMANTIC_SIMILARITY=$(awk -v seed="$(( SEED + 31337 ))" "BEGIN {srand(seed); printf \"%.6f\", rand() * 0.3 + 0.70}")
```
`EvidenceAccuracy` = random float in `[0.80, 1.00]`  
`SemanticSimilarity` = random float in `[0.70, 1.00]`

The `gather-rules-agent.sh` IS called and produces real output, but its output is **never analyzed for evidence or semantic content**. The Python module `drift_score_calculator.py` (which has real `calculate_evidence_accuracy()` and `calculate_semantic_similarity()` methods) is **never invoked** by this harness.

### Why the experiment failed
All three SC failures are caused by this stub:
- **SC-001** (20% drift reduction): Impossible to achieve when metric differences are within random noise bands
- **SC-002** (EvidenceAccuracy ≥ 0.95): Random `[0.80, 1.00]` range means ~50% of runs will fail this by chance
- **SC-003** (p < 0.05): High within-arm variance (σ ≈ 0.15) is noise from random seeding, not real policy signal

### The real implementation exists
`.specfarm/src/drift/experiment_harness.sh` (the canonical version, 434 lines) correctly calls:
```bash
python3 "$SPEC_DIR/src/drift/drift_score_calculator.py" \
    --metrics-file "$METRICS_JSON" \
    --output "$RESULT_JSON"
```
But `run_full_drift_experiment.sh` calls the stub harness (in the same `spec-013` directory), **not** the canonical one.

### Fix
In `run_full_drift_experiment.sh`, replace:
```bash
bash "$SCRIPT_DIR/experiment_harness.sh" ...
```
With:
```bash
bash "$REPO_ROOT/.specfarm/src/drift/experiment_harness.sh" ...
```
Or replace the stub `experiment_harness.sh` with the canonical implementation from `.specfarm/src/drift/experiment_harness.sh`.

## STUB-002 — `run-report.json` does not conform to its own schema

**Severity**: 🔴 CRITICAL  
**Files**: `contracts/run-report-schema.json` vs actual `artifacts/drift-testing/*/run-*/run-report.json`

### What the schema requires (`contracts/run-report-schema.json`)
Top-level required keys:
```json
["experiment_metadata", "input_configuration", "execution_summary", "metrics", "artifacts"]
```
Plus required sub-fields:
- `experiment_metadata.run_id` (pattern: `^(baseline|control|treatment)-\d{3}$`)
- `experiment_metadata.target_repo_commit` (7–40 hex char git SHA)
- `input_configuration.fixture_sha256` (64-char SHA256)
- `input_configuration.environment` (must be `"isolated_clone"`)
- `execution_summary.drift_engine_version` (semver pattern)

### What the harness actually produces
```json
{
  "experiment_metadata": { ... },
  "metrics": { ... },
  "artifacts": { ... }
}
```
**Missing**: `input_configuration`, `execution_summary`  
**Missing fields inside `experiment_metadata`**: `run_id`, `target_repo_commit`

### Impact
- VR-001 (schema validation) cannot pass — all 15 run-reports fail validation
- FR-004 (git-ref capture) is unmet — no commit SHA is recorded
- The template `run-report-template.json` has all correct fields, confirming intent, but the harness ignores the template

### Verification command
```bash
python3 - <<'EOF'
import json
with open('artifacts/drift-testing/baseline/run-1/run-report.json') as f:
    report = json.load(f)
required = {"experiment_metadata","input_configuration","execution_summary","metrics","artifacts"}
missing = required - set(report.keys())
print("Missing top-level keys:", missing)
EOF
# Output: Missing top-level keys: {'input_configuration', 'execution_summary'}
```

### Fix
Update the stub `experiment_harness.sh` to emit the full schema-conformant report (as the canonical `.specfarm/src/drift/experiment_harness.sh` does in its Phase 6 Python block).

## STUB-003 — `rules-treatment.xml` identical to `rules-control.xml` (constitutional injection missing)

**Severity**: 🔴 CRITICAL  
**Files**: `fixtures/rules-treatment.xml`, `fixtures/rules-control.xml`

### What the spec says
> Treatment: `rules.xml` + injected constitutional core  
> Treatment must have MORE rules than control (confirmed by +14.3% rule count in Phase 1 analysis)

### What actually exists
```bash
grep -c "<rule " fixtures/rules-control.xml   # → 19
grep -c "<rule " fixtures/rules-treatment.xml  # → 19
```
**Both fixtures contain exactly 19 rules.** The constitutional core injection (T008 in tasks.md) was never completed. The `rules-treatment.xml` is a copy of control with no constitutional additions.

The `run-report.json` for treatment runs correctly reports `rule_count: 19` matching the fixture. The Phase 1 analysis report claimed "+14.3% rule count (71 vs 62 rules)" — this is inconsistent with the current fixture files and likely refers to a prior experiment state.

### Related: `rules-treatment-v2.xml` is invalid XML
```
fixtures/rules-treatment-v2.xml:166: parser error : xmlParseEntityRef: no name
    <name>X. Open-Core & Freemium Governance (Strategic Plan)</name>
                        ^
```
Unescaped `&` in XML entity. This file is referenced nowhere in the scripts but indicates an attempted v2 treatment fixture that was abandoned.

### Fix
1. Complete task T008: inject constitutional core rules into treatment fixture
2. Fix `rules-treatment-v2.xml`: escape `&` → `&amp;` in the offending `<name>` element
3. Verify: `grep -c "<rule " fixtures/rules-treatment.xml` should be > 19

## STUB-004 — FR-009 dependency pre-flight validation is absent

**Severity**: 🟡 MEDIUM  
**File**: `run_full_drift_experiment.sh`

### What the spec requires (FR-009)
> System MUST validate all dependencies before execution: SpecFarm `.specfarm/` directory structure, `gather-rules-agent.sh` presence, git availability, Python 3.7+

### What actually happens
The script validates only:
1. Target repo directory exists
2. `experiment_harness.sh` exists in the same directory
3. The three fixture XML files exist

**No validation of**:
- `git` binary available
- Python 3.7+ present
- `.specfarm/src/drift/` structure in target repo
- `gather-rules-agent.sh` executable and present

If run on a repo without SpecFarm, the harness silently falls through with `WARNING: gather-rules-agent.sh not found` and still produces a (invalid) `run-report.json` — making silent failures invisible.

### Fix
Add pre-flight block to `run_full_drift_experiment.sh`:
```bash
# Dependency validation (FR-009)
command -v git >/dev/null 2>&1 || { echo "ERROR: git not found"; exit 1; }
python3 --version 2>&1 | grep -qE "Python 3\.[7-9]|Python 3\.[1-9][0-9]" || \
  { echo "ERROR: Python 3.7+ required"; exit 1; }
[[ -f "$TARGET_REPO/.specfarm/src/drift/drift_engine.sh" ]] || \
  { echo "ERROR: SpecFarm drift engine not found in target repo"; exit 1; }
[[ -f "$TARGET_REPO/.specfarm/agents/gather-rules-agent.sh" ]] || \
  { echo "ERROR: gather-rules-agent.sh not found in target repo"; exit 1; }
```

## STUB-005 — `gathered_rule_count` always zero (wrong grep pattern)

**Severity**: 🟡 MEDIUM  
**File**: `experiment_harness.sh` line 129

### What the code does
```bash
GATHERED_RULE_COUNT=$(echo "$GATHERED_RULES" | grep -c "^### " || true)
```
This counts headings matching `^### ` (H3 in markdown).

### What the agent actually produces
`gather-rules-agent.sh --markdown` outputs rules under `## ` (H2) headers or as bullet list items — **not** `### ` headers. All 15 runs show `gathered_rule_count: 0` despite the agent successfully running for ~4 seconds and producing real output.

### Evidence
```
# From baseline/run-1/logs.txt:
Run complete. DriftScore=0.131241, FixtureRules=0, GatheredRules=0, EvidenceAccuracy=0.805695
```
The agent ran (logs show 4-second execution) but zero rules were counted.

### Fix
```bash
# Adjust pattern to match actual agent output format
GATHERED_RULE_COUNT=$(echo "$GATHERED_RULES" | grep -cE "^\*\*|^## |^- \*\*" || echo 0)
```
Or better: delegate to `drift_score_calculator.py` which has a proper rule parser.

## GOVERNANCE — Agents Must Not Add `.specfarm` Code Files

**Severity**: 🔴 CRITICAL POLICY  
**Applies to**: All agents operating in the `cypress-realworld-app` repo (and any repo with SpecFarm installed)

### Problem

During this experiment, agents generated and committed Python files (`.py`), shell scripts (`.sh`), and other code directly into `.specfarm/src/` and `.specfarm/specs/`. This is how the stub harness in `spec-013` ended up diverging from the canonical one in `.specfarm/src/drift/` — an agent created a simplified replacement and the orchestration quietly wired to the wrong file.

Specific examples found in this repo:
- `.specfarm/src/drift/drift_score_calculator.py` — added by agent, not in original SpecFarm distribution
- `.specfarm/src/experiment/test_*.py` — test files added by agent, bypassing SpecFarm's update mechanism
- `.specfarm/src/logic/stubs.md` — stub templates added by agent, no matching implementation
- `.specfarm/specs/013-constitutional-drift-testing/experiment_harness.sh` — agent-created copy that silently replaced real harness in the run path
- `.specfarm/src/drift/__pycache__/` — compiled bytecache committed to repo

### Why This Is Dangerous

1. **Silent divergence**: Two versions of the same file exist (`spec-013/experiment_harness.sh` vs `src/drift/experiment_harness.sh`). The wrapper script calls the wrong one. No error is raised.
2. **Stub proliferation**: Agent-generated files tend to be minimal stubs that pass surface-level tests but omit real logic (see STUB-001 above — `awk rand()` instead of real metric computation).
3. **Untracked side effects**: Agent `.py` files may import, modify, or shadow SpecFarm internals without going through SpecFarm's config/rules pipeline.
4. **`__pycache__` pollution**: Compiled Python bytecache in `.specfarm/src/drift/__pycache__/` should never be committed; it leaks absolute paths and platform details.

### Required Controls

**1. `.gitignore` enforcement**  
Add to `.specfarm/.gitignore` (or repo root `.gitignore`):
```
.specfarm/src/**/*.py
.specfarm/src/**/*.pyc
.specfarm/src/**/__pycache__/
.specfarm/specs/**/*.py
```

**2. Agent instruction / constitution rule**  
Add to the project constitution or agent system prompt:
> Agents MUST NOT create, modify, or delete files under `.specfarm/src/` or `.specfarm/bin/` unless the task explicitly and specifically names the target file. Agents MUST NOT add new `.py` files anywhere under `.specfarm/`. Changes to SpecFarm internals must go through a human-reviewed PR.

**3. Pre-commit hook**  
```bash
# .specfarm/hooks/pre-commit (add to .git/hooks/pre-commit)
# Block agent-added .py files in .specfarm
if git diff --cached --name-only | grep -qE '^\.specfarm/.*\.py$'; then
  echo "ERROR: Blocked attempt to commit .py files under .specfarm/"
  echo "  Remove these files or get explicit human approval before committing."
  git diff --cached --name-only | grep -E '^\.specfarm/.*\.py$'
  exit 1
fi
```

**4. Audit command**  
Run periodically to detect agent-added files that shouldn't be there:
```bash
# Find .py files under .specfarm (should be zero in a clean state)
find .specfarm -name "*.py" -o -name "*.pyc" -o -name "__pycache__" | sort

# Find .specfarm files not in the original SpecFarm manifest
# (requires a manifest file — consider adding one)
git log --all --diff-filter=A --name-only --pretty=format: -- '.specfarm/src/**/*.py' | sort -u
```

## Root Cause of Phase 1 Experimental Failures

The Phase 1 analysis (in `spec.md` § Experimental Results) attributed failures to:
1. High within-arm variance
2. Metric calibration issue
3. Agent insensitivity
4. Insufficient statistical power (N=5)

**All four root causes are downstream of STUB-001.** The high within-arm variance (~0.15) is the natural spread of `awk rand() * 0.2 + 0.80` multiplied through the DriftScore formula. No amount of N increase or formula recalibration will produce meaningful results until real metrics replace the random number generators.

The Phase 2 roadmap in `CORRECTIVE_ACTIONS.md` proposes actions that are valid engineering responses to genuine measurement problems — but they will have no effect until the random metric stubs are replaced with real implementations.

**Recommended first action**: Wire `experiment_harness.sh` to call `drift_score_calculator.py` (which already exists and passes all 13 unit tests) instead of `awk rand()`.
